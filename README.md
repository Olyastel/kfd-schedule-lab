# «Ничего не падает» — работа с расписанием

Консольное приложение на Kotlin для работы с расписанием занятий. Реализует защищённую доменную модель, аудит операций и строгую обработку ошибок входных данных.

## Сборка и запуск

### Требования
- JDK 25
- Python 3.10+ (для скриптов проверки)
- Gradle Wrapper

### Команды
Сборка приложения и создание исполняемых скриптов:
```bash
./gradlew build :app:installDist
```

Запуск команд:
```bash
# Период занятий
./app/build/install/schedule/bin/schedule period --file samples/clean.txt --from 2026-09-28 --to 2027-05-13

# Фильтр по типу
./app/build/install/schedule/bin/schedule type --file samples/dirty.txt --type EXAM

# Отчёт об ошибках
./app/build/install/schedule/bin/schedule errors --file samples/dirty.txt
```

Автоматическая проверка решения:
```bash
python tools/verify.py
```

## Архитектура и принятые решения

### Выбор типов: class вместо data class
Для классов модели (`Lecture`, `Practice`, `Exam`, `Cancelled`) использованы обычные `class`, а не `data class`.

**Причины:**
1. **Контроль над конструктором.** `data class` требует, чтобы все параметры первичного конструктора были свойствами (`val`/`var`). Это мешает реализации защиты коллекций через приватный параметр и отдельное публичное свойство.
2. **Отсутствие copy().** Метод `copy()` в `data class` создаёт поверхностную копию, которая может обойти инварианты и проверки валидации. Использование обычного класса исключает этот риск.
3. **Явная иммутабельность.** Все свойства объявлены как `val`, а списки защищены на уровне инициализации, что делает состояние объекта предсказуемым.

### Защита коллекций
Список преподавателей (`teachers`) защищён от внешних изменений двумя способами:

1. **Копирование при создании.** В конструкторе входной список оборачивается в `.toList()`, создавая независимую копию. Изменение исходного `MutableList` после создания объекта не влияет на занятие.
2. **Unmodifiable wrapper.** Копия дополнительно оборачивается в `Collections.unmodifiableList()`. Это гарантирует, что даже если кто-то попытается привести полученный список к `MutableList` и изменить его, будет выброшено `UnsupportedOperationException`. Приведение `as? MutableList` вернёт `null` или безопасную обёртку, но не оригинальный изменяемый список.

### Делегирование и аудит
Класс `AuditedSessionRepository` реализует интерфейс `SessionRepository` через делегирование (`by delegate`).

**Почему переопределить только add недостаточно?**
Метод `addAll` является самостоятельной операцией интерфейса. Если реализовать только `add`, то вызов `addAll` пройдёт напрямую к делегату, минуя логику журналирования. Журнал будет неполным: событие добавления пакета из N элементов не зафиксируется. Поэтому необходимо явно переопределять оба метода (`add` и `addAll`), чтобы каждое обращение к реестрию оставляло след в аудите.

### Ошибки как данные
Результат парсинга строки представлен sealed-интерфейсом `ParseResult` с вариантами `Success` и `Failure`. Причина ошибки (`ParseError`) также является структурированными данными, а не текстовым сообщением. Преобразование в человекочитаемый формат происходит отдельно в функции `formatParseError`. Это позволяет:
- Тестировать логику обнаружения ошибок независимо от формата вывода.
- Легко добавлять новые типы ошибок без изменения кода форматирования.
- Гарантировать корректное экранирование спецсимволов в сообщениях.

## Попытки сломать модель

В тестовом наборе `ModelAndRepositoryTest` реализованы следующие проверки инвариантов:

1. **Пустая тема / пробелы.** Создание занятия с `topic = ""` или `"   "` выбрасывает `IllegalArgumentException`.
2. **Недопустимый год.** Год 0 или 10000 блокируется проверкой `require(date.year in 1..9999)`.
3. **Действующее занятие без учителей.** `Lecture` с пустым списком преподавателей не может быть создан.
4. **Экзамен с одним учителем.** `Exam` требует минимум двух преподавателей.
5. **Дубликаты учителей.** Список `["Ivanov", "Ivanov"]` отвергается.
6. **Внешняя мутация списка.** Передача `mutableListOf` в конструктор и последующий `clear()` не влияют на объект (проверка копии).
7. **Изменение через геттер.** Попытка привести `session.teachers` к `MutableList` и добавить элемент завершается неудачей (проверка unmodifiable wrapper).
8. **Снимок реестра.** Список, полученный через `all()`, не меняется при последующем добавлении занятий в реестрий.
9. **Журналирование.** Проверка корректности счётчиков и событий аудита при одиночном и пакетном добавлении.
